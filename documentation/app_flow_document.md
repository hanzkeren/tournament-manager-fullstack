# App Flow Document for Tournament Manager Fullstack

## Onboarding and Sign-In/Sign-Up
When a new user arrives at the application, the system first checks for an active session. If none is found, the user is redirected to the sign-in page. On this page, the user can enter their email and password to log in. Below the login form, a link to the sign-up page invites new users to register. On the sign-up page, the user fills in their email, chooses a password, and submits the form. The frontend sends these details to the authentication endpoint on your Express API. If the registration is successful, the API responds with a JSON Web Token stored in a secure cookie, and the user is automatically redirected to the dashboard. To sign out, the user clicks the profile avatar in the header and selects the “Sign Out” option. This action clears the session cookie and sends them back to the sign-in screen. Password recovery is not implemented in this starter version; users who forget their credentials see an inline message advising them to contact support.

## Main Dashboard or Home Page
After signing in, the user lands on the main dashboard page. The layout features a vertical sidebar on the left with navigation links for Dashboard Overview, Tournaments, Users, and Settings. At the top of the page, a header bar displays the application logo on the left and a profile avatar on the right. The central area of the dashboard shows a welcome message and summary widgets such as total tournaments, active users, and recent activity. From here, the user can click any sidebar link to move to a different section of the admin interface. The sidebar remains visible as the user navigates, and the header allows quick access to sign out or open the settings menu.

## Detailed Feature Flows and Page Transitions
The Tournaments section lists all created tournaments in a table. When the user clicks the Tournaments link in the sidebar, the app fetches the list from the API using the JWT token in the request header. The page shows each tournament’s name, date, and status. A button labeled “Create Tournament” appears above the table. Clicking that button opens a form page where the user enters the tournament name, start date, divisions, and other details. Upon submission, the form data is sent to the backend, and after a successful response, the user is redirected back to the tournament list where the new entry appears.

From the tournament list, clicking on a row navigates the user to the Tournament Detail page. This page displays bracket visualization, match schedules, and options to enter results. When the user updates match scores and clicks “Save,” the frontend makes an API call to update the database, then shows a confirmation message and refreshes the bracket view.

In the Users section, the app retrieves and displays all registered users. Each user can be edited by clicking an Edit button next to their name. This takes the user to a profile edit page where email, name, and role can be changed. Saving sends an HTTP PUT request to the backend. After success, the interface shows a toast message and returns to the user list. From this page a superadmin can also revoke access by clicking a Delete button, prompting a confirmation dialog before removing the user.

## Settings and Account Management
When the user selects Settings from the sidebar, they arrive at the Account Settings page. Here they can update personal information such as display name and contact email. A separate Change Password section allows them to enter their current password and a new password twice for confirmation. Submitting either form triggers an API call to update the user’s profile or credentials. Upon a successful update, the page displays a success banner. A back arrow at the top returns the user to the Dashboard Overview.

## Error States and Alternate Paths
If the user enters incorrect credentials on the sign-in page, an inline error message appears under the form fields stating that the email or password is invalid, and the fields are cleared for another attempt. When attempting to access any protected route without a valid session, the user is automatically redirected to the sign-in page. If a network error occurs during an API request—such as fetching tournaments or saving match results—a toast notification informs the user of a connectivity issue, and the application retries the request when the user clicks a Retry button. On form pages, invalid input triggers field-level validation messages highlighting the problem. If the user navigates to a URL that does not exist, a 404 page with a helpful message and a link back to the dashboard is shown. Attempts to perform actions without sufficient permission result in a 403 page explaining that access is denied.

## Conclusion and Overall App Journey
A new user begins by visiting the app and registering with an email and password. After being redirected to the dashboard, they see an overview of their tournaments and can navigate to different sections using the sidebar. They create and manage tournaments, record match results, and view updated brackets all from the admin interface. Through the settings page, they maintain their profile and update their password. Throughout the entire journey, authentication guards protect each route, and error messages guide the user back on track whenever something goes wrong. This flow supports the typical end goal of an admin: to set up tournaments, oversee matches, and ensure the platform runs smoothly every day.
